    Baseado em Foundry · Custom policy definition e Azure Policy · Tutorial.

    1

    Anatomia da policyRule

    Toda Custom Policy tem três blocos obrigatórios:

    • mode — All (avalia qualquer resource type, inclusive RG/subscription) ou Indexed (só resources que suportam tags/location).
    • parameters — variáveis injetadas no assignment. No nosso caso, effect com valores Deny | Audit | Disabled, permitindo soft-launch.
    • policyRule — condição if (lógica boolean: allOf, anyOf, not, field, count) + ação then (effect).

    Aliases relevantes pro Foundry: Microsoft.CognitiveServices/accounts/projects/agents, Microsoft.MachineLearningServices/workspaces/onlineEndpoints.

    2

    Effects disponíveis

    • Deny — bloqueia PUT/PATCH em pre-flight. Recurso nunca é criado. Usado p/ alto risco
    • Audit — permite criar mas registra non-compliant no Compliance dashboard. Médio risco
    • Modify — adiciona/altera tags ou campos automaticamente (ex: forçar tags['costCenter']).
    • DeployIfNotExists — remediation: dispara um ARM template (ex: criar Defender alert) quando o recurso não compliant é detectado.
    • AuditIfNotExists — flag se um recurso relacionado não existe (ex: agent sem Content Safety associado).
    • Disabled — desliga a regra sem deletar (útil em troubleshooting).
    3

    Lifecycle da implantação

    1. Authoring — JSON salvo em repo Git (governance/policies/agent-high-risk.json), revisado por PR.
    2. Definition — registrar no tenant/MG: az policy definition create --management-group contoso-root.
    3. Assignment — vincular a um escopo (MG, subscription, RG): az policy assignment create --scope /providers/Microsoft.Management/managementGroups/contoso-prod.
    4. Initiative (opcional) — agrupar várias definitions em um policySetDefinition para baseline corporativo Contoso.
    5. Compliance scan — Azure Policy reavalia continuamente (24h) e em todo deployment.
    6. Exemptions — caso de negócio justificado: az policy exemption create com expiração obrigatória.
    4

    Hierarquia de escopo

    Tenant Root MG (contoso)
  └─ MG: contoso-prod        ◄── assignment recomendado (cobre toda prod)
       ├─ Sub: data-platform
       │    └─ RG: rg-foundry-agents
       │         └─ Microsoft.CognitiveServices/.../agents/*
       └─ Sub: customer-experience
            └─ RG: rg-chatbot-contoso

    Quanto mais alto o escopo, mais agentes cobertos. A regra herda para baixo; exclusions podem isolar um RG de sandbox.

    Comandos reais para deploy

    # 1. Cria a Custom Policy Definition no Management Group corporativo
az policy definition create \
  --name "contoso-foundry-agent-high-risk" \
  --display-name "Contoso · Foundry Agent — Deny high-risk without Impact Assessment" \
  --description "Bloqueia agentes com finalidade=biometria OU publico=externo sem impactAssessment=approved" \
  --rules    @agent-high-risk.policyRule.json \
  --params   @agent-high-risk.parameters.json \
  --mode All \
  --management-group "contoso-root"

# 2. Atribui a policy ao escopo de produção, em modo Deny
az policy assignment create \
  --name        "deny-high-risk-agents-prod" \
  --display-name "Deny high-risk Foundry agents (prod)" \
  --policy      "contoso-foundry-agent-high-risk" \
  --scope       "/providers/Microsoft.Management/managementGroups/contoso-prod" \
  --params      '{"effect":{"value":"Deny"}}' \
  --identity-scope "/providers/Microsoft.Management/managementGroups/contoso-prod" \
  --mi-system-assigned \
  --location    "brazilsouth"

# 3. (Opcional) Soft-launch primeiro em Audit por 2 semanas
az policy assignment update \
  --name "deny-high-risk-agents-prod" \
  --params '{"effect":{"value":"Audit"}}'

# 4. Validar compliance state
az policy state list \
  --management-group "contoso-prod" \
  --filter "PolicyDefinitionName eq 'contoso-foundry-agent-high-risk' and ComplianceState eq 'NonCompliant'"

    Resultado quando um dev tenta criar um agente bloqueado

    $ az cognitiveservices account project agent create \
    --name "agente-biometria-externo" \
    --tags purpose=biometria audience=externo

ERROR: (RequestDisallowedByPolicy) Resource 'agente-biometria-externo' was disallowed by policy.
  Policy identifiers: [{
    "policyAssignment": "deny-high-risk-agents-prod",
    "policyDefinition": "contoso-foundry-agent-high-risk",
    "policyDefinitionDisplayName": "Contoso · Foundry Agent — Deny high-risk without Impact Assessment",
    "policyDefinitionEffect": "deny"
  }]
  → Para liberar: anexar tag impactAssessment=approved (via processo GRC) OU solicitar exemption.
